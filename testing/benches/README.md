# Benchmarks

The suite behind the table in the root [README](../../README.md#performance). Encode is what it measures seriously; decode arms exist but are not the focus.

## Running

Against prost you only need `protoc` on `PATH` — `prost-build` shells out to it. If your distro's is too old (Fedora still ships 3.19), run the C++ script below once and `build.rs` will use the `protoc` it builds instead.

```bash
cargo bench -p testing -- '^encode_'
cargo bench -p testing -- '^decode_'
```

Against the official C++ runtime, use the script. It needs no protobuf package at all — it builds its own, `protoc` included — and checks the rest of your toolchain, naming what to install if anything is missing; then builds protobuf from source as **static** libraries into `third_party/protobuf-cpp` (gitignored). Several minutes, first run only.

```bash
scripts/bench_cpp.sh                        # all encode groups
scripts/bench_cpp.sh --bench otlp_traces    # one target
```

After that `build.rs` finds the cache on its own, so plain `cargo bench -p testing --features cpp` is statically linked too. A shared system protobuf also satisfies the probe but **understates the C++ side** — a stub on every cross-library call, no inlining across it — so don't publish numbers from one. The feature is strict: if no runtime is found the build fails rather than silently dropping the arms, which also means `--all-features` fails without a C++ toolchain.

## Which arms to compare

Every headline group has the same five: `tacky` (forward, into a `Vec`), `tacky-rev` (backwards into a caller-sized slice), `prost`, the fair C++ arm, and that arm's cached floor.

- **`cpp-noutf8` is the fair C++ arm for proto3.** The plain `cpp` arm also validates UTF-8, which Rust gets free from `&str`, so it measures work tacky never does. proto3 groups therefore carry only the `noutf8` variant; the validating kinds are still wired through `testing/cpp/shim.cc` if you want to measure that cost yourself.
- **`cpp` is the fair arm for proto2** — there is no UTF-8 validation to switch off.
- **Never quote `*-cached`.** It reuses sizes from an already-populated message, which a real producer cannot: to have those sizes it must have run the size pass. It is the runtime's theoretical floor, useful as a reference, not as a comparand.

Two groups carry extra arms, each the single home for a diagnostic that reports the same thing everywhere:

- `encode_pprof` — `tacky-slice` (forward into a fixed slice, so `tacky-slice` vs `tacky-rev` isolates *direction* from *buffer kind*) and `tacky-rev-owned` (what compacting the tail-aligned output into an index-0 `Vec` costs).
- `encode_accesslog` — `tacky-grow` and `prost-grow`, the only arms that start from an empty `Vec` and so pay the reallocation path. Every other arm reuses a warm buffer, which is the right steady state for an exporter but hides what the first export costs.

## The published table

```bash
cargo bench -p testing --features cpp --bench comparison     -- 'encode_(pprof|accesslog)/(tacky|tacky-rev|prost|cpp-noutf8)$'
cargo bench -p testing --features cpp --bench otlp_traces    -- 'encode_otlp_traces(_512)?/(tacky|tacky-rev|prost|cpp-noutf8)$'
cargo bench -p testing --features cpp --bench otlp_logs      -- 'encode_otlp_logs/(tacky|tacky-rev|prost|cpp-noutf8)$'
cargo bench -p testing --features cpp --bench descriptor_set -- 'encode_fds_[a-z_]+/(tacky|tacky-rev|prost|cpp)$'
```

**Ratios are only meaningful within one run.** Re-running unchanged code on this hardware moves a number by several percent, and it drifts in both directions over a session, so never compare a number against one from a previous run. For an A/B, use `scripts/ab_bench.sh`, which alternates two commits and reports a median over pairs — and calibrate it by passing the same commit twice, in the same session, so you know what the box is doing right now.

`cargo bench ... -- --test` runs every arm once without measuring. That is the cheap way to check the round-trip assertions after changing a writer.

## Corpora

Two are checked-in fixtures, two are generated:

| Corpus | Source |
| :--- | :--- |
| pprof | A real Go heap profile. Vendored from [pyroscope](https://github.com/grafana/pyroscope)'s test data — AGPL-3.0, included as data only and under its own licence, not this repo's. |
| Descriptor sets | `protoc` output, regenerated by `scripts/gen_bench_fixtures.sh`. |
| OTLP traces / logs | Synthesised. No public OTLP payload dataset exists. |
| Access log | Synthesised, and *plausible* rather than real — shaped after Envoy's `HTTPAccessLogEntry`, minus the well-known types. |

For the synthesised ones the generator is part of the result, so each bench's module header spells out every count, every string-length spread, and why. Read those before trusting a number, and before changing a constant.

`--test` mode also prints each corpus's size and both encoders' byte counts, which is how the claim that tacky's output length matches prost's stays checked rather than assumed.
